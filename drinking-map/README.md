# 販物G 飲み会MAP

社員研修用の飲み会店舗管理モック。React + Vite + Leafletで作成しています。

## 起動

Node.js 20.19以上、または22.12以上を利用してください。

```bash
cd apps/drinking-map
npm install
npm run dev
```

表示されたURLをブラウザで開きます。コンテナ外から接続する場合は `npm run dev -- --host 0.0.0.0` を使ってポートを転送してください。

## 機能

- 上部に店舗の地図、下部に最終更新日の新しい順の一覧を表示。
- ピンをクリックすると店舗名・最終更新日・更新者を表示。表と地図のポップアップ内の店舗名をクリックすると、その店舗名でGoogle検索を新しいタブに開く。
- 店舗一覧の最下行にある「店舗を追加」から店舗名・最終更新日・更新者を入力。「検索」で所在地を取得し、候補を選択して「登録」で保存。
- 各行のゴミ箱の横にある「＋1」から「訪問を登録」画面を開く。店舗名は変更不可で、元の店舗の緯度・経度を引き継ぐ。最終更新日は当日、更新者は空欄となり、入力後に「登録」だけで新しい記録を追加。検索・所在地選択は不要。
- 同じ店舗を何度でも別レコードとして登録可能。表示件数はユニークな店舗数ではなく登録レコード数。
- 表の店舗名の右に「訪問数」を表示。店舗名が完全一致する現在の登録レコード数を集計し、同じ店舗の各行に「2 回」などと表示。1レコードを1訪問として数え、「＋1」からの登録完了・削除に応じて再集計。
- ゴミ箱から確認ダイアログを開き、削除を確定すると一覧とピンを削除。
- localStorageに保存し、同じブラウザでの再読み込み後も保持。

## モックの前提

- 初回だけ表示用のサンプル3店舗を表示します。最終更新日・更新者は架空、座標は概略位置です。サンプルも削除可能です。
- 保存先はブラウザ内のみです。端末間の共有やサーバー保存は行いません。
- 地図タイルはOpenStreetMap、店舗名の位置検索は公開Nominatim APIを使用するためインターネット接続が必要です。入力した店舗名が外部サービスへ送信されます。更新者名・最終更新日は送信しません。
- 店舗名のリンクをクリックするとGoogleに店舗名を検索語として送信します。更新者名・最終更新日は検索語に含めません。
- 店舗検索は通常の「店舗を追加」の「検索」操作時だけ実行し、連続リクエストを制限しています。新規店舗は検索候補から所在地を選んで登録します。「＋1」の訪問登録では検索APIを呼び出さず、保存済みの位置情報を再利用します。架空の座標を自動生成しません。
- 公開APIの利用制限・検索精度・可用性に依存する研修用構成です。本番化や大人数での研修時には、[Nominatim利用規約](https://operations.osmfoundation.org/policies/nominatim/)に沿った検索基盤を別途用意してください。
- フォントはGoogle Fontsを使用します。取得できない場合は端末のフォントで表示します。
- 認証・編集・評価・コメント等は実装していません。

## 登録データ

```json
{
	"registrationNo": "登録ごとに発行する一意のUUID",
	"storeName": "銀座ライオン 七丁目店",
	"updatedDate": "2026-10-13",
	"updatedBy": "渡邉",
	"latitude": 35.6698,
	"longitude": 139.7628
}
```

主キーは `registrationNo`（登録No）です。店舗名や検索APIの店舗IDを主キーにしないため、同じ店舗・同じ最終更新日でも登録ごとにレコードを追加します。削除は登録Noを指定した1レコードに限定します。旧形式の `id` は読み込み時に登録Noへ移行し、次回の保存時に新形式で保存します。サンプルの登録Noは `sample-1` などの固定値です。

訪問数は保存項目ではなく、既存の登録レコードから計算する表示項目です。更新者・最終更新日が異なっても店舗名が完全一致すれば合算し、同日の複数登録もそれぞれ1訪問として数えます。表記が異なる店舗名は合算しません。同名の別所在地は合算されるため、支店を区別する場合は店舗名に支店名を含めてください。削除した記録は訪問数から除外します。再読み込み時も保存レコードから再計算するため、データ移行は不要です。

スマートフォンでは列幅を確保するため、表の領域だけ横スクロールできます。

旧形式の `visitedDate`（行った日）・`registeredBy`（登録者）は、値を保持して `updatedDate`（最終更新日）・`updatedBy`（更新者）へ移行します。新旧両方の項目がある場合は新項目を優先します。最終更新日は追加画面で入力する日付で、初期値は当日です。自動更新日時ではなく、編集機能も追加していません。

表とピンに表示する数字は最終更新日順の表示番号で、登録Noとは異なります。同じ所在地の記録はピンが重なります。表の店舗名は地図の選択ではなくGoogle検索へのリンクです。

Google検索は `https://www.google.com/search?q=店舗名` をURLエンコードして開きます。リンクは `target="_blank"` と `rel="noopener noreferrer"` を設定しています。Google検索APIは使用しません。

## 店舗検索API

OpenStreetMapの公開 **Nominatim Search API**（`https://nominatim.openstreetmap.org/search`）を使用します。店舗名を `q` として送信し、`countrycodes=jp` で日本国内に限定、`format=jsonv2` と `accept-language=ja` で日本語の候補を最大5件取得します。選択した候補の `lat`・`lon` を登録時の位置として保存します。APIキーは不要です。地図の描画ライブラリはLeafletで、検索APIとは別です。
